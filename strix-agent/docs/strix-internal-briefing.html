Internal briefing

How we run Strix as a pentest assistant

Same engine as the customer story. This cut is for operators: features, toolkit, standards maps, artifacts, and the rules we do not break.

Confidential · AppSec and engineering · ~15 minutes

Role

Force multiplier for a human pentest program

We use it to

Attack authorized code, URLs, and APIs; persist proof; map coverage to a named standard; and put findings in front of developers before merge.

We do not use it to

Close residual risk, skip domain verification, dump secrets into tickets, or treat a green dashboard as a complete pentest.

Salient features

What we can count on

Attacks and proves

Agents exploit authorized apps and attach a PoC and reproduction steps when they can validate the issue — not a lint list.

Real pentest toolkit

HTTP proxy, browser, shell, exploit runtime, recon, and SAST/DAST — the same class of tools a human tester uses.

Multi-agent graph

Specialized agents split recon, exploitation, and follow-on work, share discoveries, and chain issues like a small red team.

CLI and dashboard

One engine: headless CLI for CI, or a self-hosted dashboard for orgs, schedules, PR reviews, and a findings queue.

Artifact-driven

Coverage maps and scan outputs are durable files — reports, SARIF, findings — not a chat transcript that vanishes.

Matched to standards

Pin a pentest to OWASP Top 10, ASVS, NIST, PCI DSS, and related maps. Findings are tagged to the standard and CWE.

Evidence we can act on

Severity, impact, remediation guidance, markdown, JSON, and SARIF so results land in GitHub, GitLab, and existing workflows.

Fits how we ship

PR comments, CI gates, scheduled staging scans, and agent skills so review starts before merge.

Honest coverage

Each run shows what was tested and skipped. A green dashboard is not a pass. People still own residual risk.

Toolkit

What the agents are allowed to use

Intercept and browse

HTTP interception proxy (Caido), plus an automated browser for XSS, CSRF, clickjacking, and auth-bypass flows.

Exploit and prove

Interactive shell, Python sandbox for PoCs, recon/OSINT, and SAST + DAST against the same target.

Classes we hunt

Broken access control and IDOR, injection, SSRF/XXE/RCE, XSS/CSRF, business logic, session/JWT, API authz, and LLM/MCP surfaces when in scope.

Always isolated

Each scan runs in its own Docker sandbox. Attack tooling does not sit on a laptop, and mock mode is labeled — never shown as a finished pentest.

Standards

Pentests can be matched to a named map

Select in the dashboard or pass --skill. Every testable row becomes a coverage category. Findings are tagged with the standard ID and CWE.

OWASP Top 10:2025 OWASP ASVS L1/L2 OWASP API Top 10 OWASP LLM / MCP / Agentic NIST SSDF / 800-53 NIST AI RMF PCI DSS 4.0 (technical)

This is coverage of testable controls, not a compliance certificate.

Artifact-driven architecture

Files drive the agents. Files are what we keep.

  • In — standards and vulnerability skills are markdown artifacts. Drop a map in; no hardcoded registry of “what we test.”
  • During — the root agent spawns specialists from those maps and writes findings as they are proven, not as a dump at the end.
  • Out — each run persists a pentest report, per-finding markdown, JSON, SARIF, and coverage under strix_runs/.
  • Reuse — dashboard, CI, strix view, and PR comments all read those artifacts. Chat is optional commentary on top.

How we run it

Same engine, two doors

CLI

Headless scans against a repo, URL, domain, or IP. Use -n in CI, pin a standard with --skill, and fail the job on validated findings.

Self-hosted dashboard

docker compose up --build — orgs, connected repos/domains, scheduled scans, PR reviews, chat over a run, findings queue at localhost:8095.

Operating rules

People still own the decision

  • Only authorized testers start scans, and only against assets we own or have written permission to test.
  • Findings are proposed evidence. Confirm, dispute, or defer before residual-risk wording changes.
  • Live targets require domain verification. Unverified hosts are not in-scope.
  • Secrets stay out of tickets. Mock or incomplete runs stay labeled. Telemetry stays off unless we turn it on.

Limits we will say out loud

A strong assistant. Not a complete pentest on every run.

Coverage has a budget

Scan mode, time, and target type cap what gets exercised. Green means nothing proven in what we tested — not that the product is safe.

Not the system of record

SSO/MFA at enterprise scale, portfolio GRC, and immutable compliance audit are still platform and human work. Strix feeds that work.

Discussion

What we run next, and who is allowed to start it

Name the apps, the standard map, the authorized testers, and the rule that residual-risk language still comes from AppSec.
