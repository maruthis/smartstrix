Business stakeholder briefing

Strix: an AI pentest assistant for authorized targets

A self-hosted way to find, prove, and track application security issues in hours — while people still own residual-risk sign-off.

Confidential · for business stakeholders · ~18 minutes

The problem

Release speed has outrun how we test for real-world abuse

What the business feels

Features ship continuously. Security reviews arrive late, or only on the assets we remembered to book. High-severity issues still show up in production and in customer questionnaires.

What a scanner-only answer misses

SAST/DAST and dependency scans are necessary. They do not reliably prove broken access control, business-logic abuse, or AI/MCP-specific failure modes — and they do not produce an exploit trail a developer can act on.

What this is

Strix is a force multiplier for a human pentest program

It is

An autonomous AI pentesting assistant. It attacks authorized code, URLs, APIs, and related surfaces, then returns findings with proof, remediation, and a report a team can work from.

It is not

A substitute for residual-risk sign-off, a complete compliance system of record, or a license to test anything we do not own or have written permission to test.

Salient features

What we can count on

Attacks and proves

Agents exploit authorized apps and attach a PoC and reproduction steps when they can validate the issue — not a lint list.

Real pentest toolkit

HTTP proxy, browser, shell, exploit runtime, recon, and SAST/DAST — the same class of tools a human tester uses.

Multi-agent graph

Specialized agents split recon, exploitation, and follow-on work, share discoveries, and chain issues like a small red team.

CLI and dashboard

One engine: headless CLI for CI, or a self-hosted dashboard for orgs, schedules, PR reviews, and a findings queue.

Artifact-driven

Coverage maps and scan outputs are durable files — reports, SARIF, findings — not a chat transcript that vanishes.

Matched to standards

Pin a pentest to OWASP Top 10, ASVS, NIST, PCI DSS, and related maps. Findings are tagged to the standard and CWE.

Evidence we can act on

Severity, impact, remediation guidance, markdown, JSON, and SARIF so results land in GitHub, GitLab, and existing workflows.

Fits how we ship

PR comments, CI gates, scheduled staging scans, and agent skills so review starts before merge.

Honest coverage

Each run shows what was tested and skipped. A green dashboard is not a pass. People still own residual risk.

Where it earns its keep

Four jobs we can give it tomorrow

Application security

White-box review of a repo plus live-target testing, so developers get a finding they can reproduce — not a CVE ID with no path.

Rapid pentest

Hours, not weeks, on a staging URL or service we are authorized to hit. Useful before a launch, a customer demo, or a high-risk change.

CI / pull requests

Scan the diff, comment on the PR, and fail the job when real issues appear. Security review starts before merge, not after release.

Focused hunts

Same engine for bug-bounty style depth or AI/MCP surfaces when those products are in scope — without buying a second toolchain.

How it works

Artifact-driven architecture — data stays with us

  • Artifact-driven — coverage maps and scan outputs are durable files (standards markdown, reports, SARIF, findings), not a vanishing chat transcript.
  • CLI or self-hosted dashboard — same engine for a named target, scheduled scans, PR reviews, and a findings queue.
  • Isolated execution — each scan runs in its own sandbox so the attack tooling does not sit on a laptop.
  • Our model, our keys — we choose the LLM provider; we are not locked to a vendor pentest cloud.

What you get

Evidence, artifacts, and a standard we can name

Findings with proof

Severity, impact, reproduction steps, and a PoC where the agent could demonstrate the issue — tagged to the standard and CWE.

Durable artifacts

Markdown reports, JSON, and SARIF so results can land in GitHub/GitLab and existing issue workflows — and survive after the scan ends.

Mapped to standards

Match a pentest to OWASP Top 10, ASVS, NIST, PCI DSS, and related maps. Coverage shows which rows were tested. Silence is not a pass.

Operating model

People still own the decision. Strix owns the grunt work.

  • Only authorized testers start scans, and only against assets we own or have written permission to test.
  • Findings are proposed evidence. A human confirms, disputes, or defers before we change residual-risk language.
  • Live targets require domain verification. The assistant will not treat an unverified host as in-scope.
  • Secrets and credential-shaped notes stay out of tickets. Scan integrity is visible: mock mode is labeled, never shown as a complete pentest.

Honest limits

What we are not asking you to believe

Not a complete pentest on every run

Budget, scan mode, and target type cap what gets exercised. A green dashboard means ‘nothing proven in what we tested,’ not ‘the product is safe.’

Not the system of record yet

Portfolio GRC, SSO/MFA at enterprise scale, and immutable compliance audit are still human and platform work. Strix feeds that work; it does not replace it.

Why it is worth sponsoring

The return is cycle time and fewer surprises — not a magic score

  • Faster feedback — hours to a working PoC instead of a queued engagement for every change.
  • Earlier in the path — PR comments and scheduled scans catch issues before they become incident or audit findings.
  • One motion for web, API, and AI surfaces — including LLM/MCP classes when those products are in scope.
  • Self-hosted control — source and scan traffic stay in our environment; we pick the model and the operators.

The ask

Sponsor a 90-day assistant pilot — not a tool rollout

  • Name 2–3 production-adjacent apps (staging URLs + repos) we are authorized to test.
  • Name an AppSec owner and a small authorized-tester group. Residual-risk wording stays with them.
  • Turn on PR scanning for those repos and a weekly scheduled scan on staging.
  • Review after 90 days: time-to-first-validated-finding, escaped high/criticals, and whether the team still trusts the coverage story.
